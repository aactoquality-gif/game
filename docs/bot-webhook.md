# Вебхук бота и удаление данных (/deletedata)

Игрок пишет боту `/deletedata` → бот предупреждает, что удалится и что купленное пропадёт, и предлагает
`/deletedata_confirm` → сервер удаляет все записи, связанные с его Telegram ID, и отвечает, сколько удалено.

Код — `server/bot.mjs`, перезапись файла — `server/events-store.mjs`, тесты — `tests/bot-deletedata.test.mjs`.

## Что удаляется

| Где | Что | Удаляется |
|---|---|---|
| `/data/events.jsonl` | события чтения с этим `user_id` | да, все |
| покупки (с Г3) | записи о покупках с этим ID | да — **при подключении платежей добавить их в `/deletedata`** |
| Telegram CloudStorage, `localStorage` | прогресс чтения | нет: сервер к ним доступа не имеет |
| журнал хостинга | `user=ID` в строках `[events]` и `[bot]` | нет: живёт по правилам Amvera |

Удаляются только записи этого ID — анонимные события браузера и чужие ID остаются. Если игрок снова откроет игру,
статистика по его ID начнёт копиться заново: бот об этом предупреждает.

## Как включить (один раз)

1. **Секрет.** Придумай строку из латиницы, цифр, `_` и `-`, 32+ символа (например, результат `openssl rand -hex 32`).
   В Amvera → проект → «Переменные» добавь секрет `BOT_WEBHOOK_SECRET` с этим значением. Перезапусти приложение.
   Без переменной вебхук выключен: `/api/telegram/webhook` отвечает 404, в журнале при запуске — предупреждение.
2. **Проверь, нет ли уже вебхука.** Открой в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`. Если в ответе `url` не пустой — бот уже шлёт апдейты
   куда-то ещё: новый вебхук его заменит. Сначала разберись, что там.
3. **Поставь вебхук.** Открой в браузере (одной строкой, свои токен, домен и секрет):
   ```
   https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<домен>/api/telegram/webhook&secret_token=<СЕКРЕТ>&allowed_updates=%5B%22message%22%5D
   ```
   Ответ `{"ok":true,...}` — готово. Токен в адресной строке остаётся в истории браузера: потом почисти её.
4. **Команда в меню бота.** В @BotFather → `/setcommands` → твой бот → список команд целиком
   (команда заменяет весь список — впиши и те, что уже есть):
   ```
   deletedata - Удалить мои данные с сервера
   ```
5. **Проверка.** Напиши боту `/deletedata` — придёт предупреждение. `/deletedata_confirm` — придёт число удалённых
   записей. В журнале Amvera появятся строки `[bot] deletedata_request user=…` и `[bot] deletedata_done user=… removed=…`.

## Правила

- Апдейт целиком не логировать и не сохранять: в нём имя, username, текст сообщения. В журнал — только ID и тип события.
- Ответ — в теле ответа на вебхук (`{"method":"sendMessage",...}`), исходящих запросов к `api.telegram.org` нет.
  Узнать, дошёл ли ответ, нельзя — так устроен этот способ.
- Платежи (Г3) пойдут через этот же вебхук: `pre_checkout_query` и `successful_payment`. Тогда в `allowed_updates`
  добавится `pre_checkout_query`, а `/deletedata` начнёт удалять и покупки.
- Срок ответа на запрос об удалении по GDPR — до месяца. Команда удаляет сразу; запросы на почту — вручную.
