# Автопроверки: `check:rules` и `check:ui`

Справочник для того, кто правит проверки или разбирает отчёт. Короткие правила для агента — в `CLAUDE.md`.

`npm run check:ui` = `check:rules` → сборка (`tsc` + `vite build`) → проверка интерфейса в браузере.
Красная любая из трёх частей — шаг не сдан (правило 10).

- `✗` — ошибка, проверка красная (код выхода 1).
- `!` — замечание, не блокирует. Новые замечания перечисляются в отчёте шага: это кандидаты в отдельные задачи.
- Ослаблять проверки ради зелёного цвета нельзя (правило 14): менять `✗` на `!`, расширять исключения,
  поднимать бюджет, удалять ожидания. Согласованное изменение — в отчёт, раздел «Изменения в проверках».

## `check:rules` — правила без браузера (~1 с)

`scripts/check-rules.mjs`, отдельно — `npm run check:rules`. В каждой находке: файл и строка, что не так,
ссылка на правило `CLAUDE.md` и что сделать вместо.

| Раздел | Что проверяет | Правило |
|---|---|---|
| код | `fetch` только в `api.ts` (и прежние в `engine.ts`, `analytics.ts`); `sendBeacon` — только `analytics.ts`; без `XMLHttpRequest` / `WebSocket` / `EventSource` | 5 |
| код | `window.Telegram` — только `telegram.ts` | инвариант «Telegram API» |
| код | `localStorage` / `sessionStorage` / `indexedDB` — только `storage.ts` и `analytics.ts`; `CloudStorage` — `storage.ts`, `telegram.ts` | 7 |
| код | без `innerHTML` / `outerHTML` / `insertAdjacentHTML` / `document.write`; без `alert` / `confirm` / `prompt`; без `window.open` и `location.href =` вне `telegram.ts` | 15 |
| код | экраны и компоненты (`src/ui`, `src/layout`) не импортируют `api` / `sync` (кроме `import type`) | 5 |
| код | заглушки вместо кода: `// ...`, «код без изменений», «остальное как было», «rest of code» — в `src`, `scripts`, `server` | 2 |
| CSS | `!important` — только внутри `@media (prefers-reduced-motion)`; `z-index` — только `var(--z-*)`; токены `--z-*` и `:root` — только в `style.css` | 4 |
| CSS | `@media` по ширине / высоте / ориентации окна — только `src/layout/shell.css` | 4 |
| CSS | значение в `cqh` — строкой выше то же свойство в `vh` (старые WebView) | 4 |
| CSS компонентов | цвета только через переменные (допустима чёрная тень `rgba(0, 0, 0, …)`); в каждом селекторе есть класс; в `src/ui/kit` — класс `ui-*` | 4 |
| зависимости | `dependencies` пусто; `devDependencies` — только typescript, vite, playwright-core | 8 |
| контент | каталог: `firstLaunch: "story"`, `defaultStory` существует, id историй уникальны, эпизоды 1…N, у доступного эпизода есть файл | инвариант H3, «Игровая модель» |
| контент | глава: старт существует; у экрана либо `next`, либо `choices`, у `end` — ничего; ссылки ведут на экраны; из каждого экрана достижим конец; есть `end`; `kind` и `type` из списка; цена — целое > 0; моральный выбор без цены; `effects` — целые; id выборов уникальны во всей истории | инвариант «Глава», «Игровая модель» |
| контент `!` | недостижимый экран; выбор из одного варианта; развилка без бесплатного варианта; id не `a-z0-9_`; файл главы не в каталоге; картинка с чужого адреса | «Игровая модель» |
| публикация | сверка с `origin/main` (прод): пропал id выбора или доступной истории — `✗`; пропал id экрана — `!` (игроки на нём начнут эпизод заново, счётчики посчитаются дважды) | инвариант «Глава» |
| самопроверка | на каждое правило — образец с нарушением (должен поймать) и образцы допустимого кода (должен молчать) | 14 |

Нет `origin/main` (свежий клон без fetch) — сверка с продом пропускается с пометкой: `git fetch origin main`.

## `check:ui` — интерфейс в браузере

Отчёт со скриншотами: `.checks/ui/report.html`. Браузер: `CHROME_PATH` → Chromium Playwright → Google Chrome → Microsoft Edge.
Быстрый прогон части сценариев: `CHECK_ONLY=390-telegram,320-browser npm run check:ui`; только стенды —
`CHECK_ONLY=shell` или `CHECK_ONLY=kit`.

**Игра** — 320×568, 390×844, 1440×900 × режимы «браузер» и «Telegram» (имитация WebApp: подписанный initData,
системная «Назад», CloudStorage, home bar 34 px). На 390 — эпизод целиком, на остальных — до первого выбора.
Проверяет: первый запуск, листание, выбор, паузу, «Назад», меню, сохранение после перезапуска, события аналитики,
вызовы Telegram, вёрстку (горизонтальный скролл, обрезанные блоки, документ зафиксирован, слои z-index,
незаполненные подстановки `{имя}`, у каждой кнопки есть цель аналитики, зона касания ≥ 44 px), бюджет сборки,
строки интерфейса мимо `t()` (кириллица в литералах `src/`), имена событий из каталога и проходят фильтр сервера,
состояние приложения (платформа, маршрут, конфиг). Кнопки поверх сцены и обложки — кнопки-иконки kit; в Telegram
на экране истории нет своей «Назад».
В каждом экране: экраны и слои внутри кадра, чтение — без хедера и таббара, пустые зоны скрыты; в браузере — три
пути «Назад»: Esc, системная «Назад» (история), кнопка на экране.

**Сценарии** — флаги включены через `?ff=` → баланс и входящие доходят до состояния; конфиг недоступен → игра
стартует на значениях по умолчанию; перенос старого сохранения v1.

**Регресс** (1440 браузер и 320 Telegram): клавиатура (Enter, цифры), «Начать сначала» с диалогом поверх шторки,
эпизод до конца, «Перечитать?» → «Отмена», тост — всё внутри кадра, аналитика нажатий.

**Стенд каркаса** `layout.html` — 8 размеров (телефоны, Telegram fullscreen, режим чтения, телефон боком, планшет,
низкое и обычное окно десктопа): размер и положение кадра, зоны, брейкпоинт `@container`, `position: fixed`
не выходит за кадр.

**Стенд компонентов** `kit.html` — 320, 390, 1440:
- кнопка-иконка, бейдж, чип: каждое состояние есть и видно (отличается от обычного), зона касания 44 px с углами,
  круг 40 / 32 px, контраст (текст ≥ 4.5, иконки ≥ 3), подписи для скринридера, цели аналитики, всё внутри кадра;
  живые примеры — настоящими нажатиями; на 1440 настоящие наведение, нажатие и фокус совпадают с замороженными
  на стенде; на телефоне наведение не «залипает»;
- шторка и диалог (плюс `kit-390-tg` — Telegram): закрывают «Назад» Telegram / Esc (сначала верхний слой), фон,
  крестик, жест вниз; фокус внутри и обратно на кнопку, экран под слоем `inert`, двойной тап срабатывает один раз,
  длинная шторка прокручивается; в игре — пауза и диалоги, то же плюс аналитика закрытия (`pause.close`, `dialog.*`);
- переключатель и сегменты: роли, все состояния, касание, клавиатура (пробел, стрелки, End, пропуск недоступного);
  в игре — «Размер текста» в паузе (касание и стрелка);
- поле ввода и экранная клавиатура (`kit-320`, `kit-390`, `kit-390-tg`, `kit-768`, `kit-844x390`): имитация клавиатуры
  iOS (перекрывает экран, сдвиг страницы) обычной, цифровой и с автозаполнением, и Android (экран ужимается) — поле
  внизу экрана, в шторке и ошибка под ним всегда над клавиатурой, кадр в видимой части, таббар спрятан; вид поля →
  своя клавиатура, шрифт ≥ 16 px.

## Как добавлять проверки

- Новый экран или элемент → сценарий в `scripts/check-ui.mjs` в том же шаге (правило 10).
- Новое правило в `CLAUDE.md`, которое можно проверить по коду, → функция в `scripts/check-rules.mjs` плюс два образца
  в самопроверке: нарушение (ловит) и допустимый код (молчит).
- Сообщение об ошибке пишется для того, кто её исправит: что не так, где, что сделать вместо.

## CI

`.github/workflows/check.yml`: на каждый PR в `main` (и вручную — Run workflow) — `npm ci` → `npm run check:ui` в Ubuntu
с Google Chrome; перед этим подтягивается `origin/main` для сверки с продом. Отчёт со скриншотами — артефакт
`check-ui-report` у прогона (вкладка Actions → прогон → Artifacts), хранится 14 дней.

Чтобы красная проверка не давала влить PR, владелец включает в настройках репозитория защиту ветки `main` с обязательной
проверкой `check`. Это решение владельца: агент настройки репозитория не меняет.
