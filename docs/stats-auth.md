# Доступ к статистике

Открывайте `/api/stats` по HTTPS. В Telegram администратор входит автоматически по
подписи `initData`; в браузере — по шестизначному коду из письма. Срок кода — 10 минут.
Сессия действует 8 часов без продления: от Telegram `auth_date` либо проверки email.
В Telegram Web Strict-cookie может блокироваться внутри iframe: откройте чистую
ссылку во внешнем браузере и войдите по email. Нативные WebView требуют проверки на
реальном iOS/Android/Desktop перед выпуском. Сам факт входа в Telegram не даёт доступ.

## Окружение

| Переменная | Значение |
| --- | --- |
| `STATS_ORIGIN` | Точный HTTPS origin приложения, без завершающего `/` и пути |
| `STATS_SESSION_SECRET` | Постоянный случайный секрет не короче 32 байт; например результат `openssl rand -hex 32` |
| `STATS_ADMIN_TELEGRAM_IDS` | Разрешённые числовые Telegram ID через запятую |
| `STATS_ADMIN_EMAILS` | Разрешённые email через запятую; регистр не учитывается |
| `BOT_TOKEN` | Токен бота, необходим только для Telegram-входа |
| `RESEND_API_KEY` | API-ключ Resend, необходим для email-входа |
| `STATS_EMAIL_FROM` | Отправитель с подтверждённого в Resend домена |
| `TRUSTED_PROXY_CIDRS` | Доверенные адреса/CIDR прокси через запятую; по умолчанию пусто |
| `DATA_DIR` | Постоянный каталог данных; в Amvera `/data` |

Задавайте секреты только в окружении платформы. Не генерируйте новый секрет при
каждом запуске: его смена отзывает все сессии и делает текущие коды недействительными.
Изменение списка администраторов применяется после перезапуска и проверяется при
каждом запросе, в том числе для ранее выпущенных cookie. Пустой список запрещает
соответствующий способ входа. Неполные настройки не открывают доступ.

Cookie `__Host-stats_session` имеет HttpOnly, Secure, SameSite=Strict, Path=/, без Domain.
Не отключайте Secure для разработки: используйте локальный HTTPS reverse proxy с
соответствующим STATS_ORIGIN. Сессии не хранятся на сервере. Для работы нужен один
процесс/одна реплика; файловое состояние не поддерживает конкурентные процессы.

## OTP и ограничения

Resend вызывается через native fetch: `POST https://api.resend.com/emails` (тайм-аут 10 с).
Ответ запроса кода всегда нейтрален: это не подтверждение доставки. Сбой доставки
пишется как обезличенное предупреждение; код не активируется. Никакие токены, коды,
initData или email не записываются в журналы авторизации.

`stats-auth-state.json` хранит HMAC кодов, адреса получателей и скользящие счётчики
(идентификаторы IP/email в счётчиках хешированы). Права файла 0600; замена атомарная
с fsync. Сохраняйте каталог между деплоями, ограничьте доступ к резервным копиям.
Лимиты за 10 минут: 3 запроса письма и 5 проверок, отдельно по IP и email. Повторная
отправка не обнуляет попытки; успешный код погашается до выдачи cookie. Удаление
файла сбрасывает защиту — не используйте это как обычный способ восстановления.
При повреждении/ошибке диска email-вход закрывается до устранения причины и рестарта.
Лимит состояния: 10000 записей / 4 МиБ. Истёкшие записи очищаются при операциях.

По умолчанию используется IP TCP-соединения. Настраивайте TRUSTED_PROXY_CIDRS только
после проверки реальной цепочки Amvera: каждый доверенный прокси должен безопасно
дописывать/заменять X-Forwarded-For. Разбор идёт справа налево до первого недоверенного
адреса. Без настройки все запросы от одного прокси делят общий IP-лимит. Никогда не
задавайте 0.0.0.0/0 или ::/0 для удобства. Это правило применяется и к сбору событий.

## HTTP-контракт

POST JSON с Origin, точно совпадающим с STATS_ORIGIN:

- `/api/stats/auth/telegram`: `{ "initData": "..." }`;
- `/api/stats/auth/email/request`: `{ "email": "..." }`, ответ 202;
- `/api/stats/auth/email/verify`: `{ "email": "...", "code": "123456" }`.

Успешный вход: 200, `{ "ok": true }`, токен только в Set-Cookie.
Ошибки: 400 — данные, 403 — Origin/доступ/код, 415 — не JSON, 429 — лимит
(с Retry-After), 503 — конфигурация или хранилище недоступны. Ответы no-store.

Отчёт `/api/stats`, JSON `?format=json`, файл `/api/stats/download` и старый алиас
`/api/events.jsonl` защищены общей проверкой cookie. Без входа отчёт показывает форму,
JSON и скачивание возвращают 401. Старый query-параметр key удаляется редиректом,
никогда не авторизует; STATS_KEY больше не используется. Старые копии ключа в истории
и access.log автоматически не удаляются. До выпуска удалите STATS_KEY из окружения.

## Проверка и выпуск

`npm run test:server` — серверные проверки с синтетическими данными, без реальных писем.
`npm run check:ui` — интерфейс игры и входа, включая HTTPS cookie, реальные маршруты
сервера и имитацию Telegram. Настройте Resend/домен и проверьте реальное письмо перед
production, затем проверьте Telegram WebView и скачивание. Публикация в main запускает
деплой Amvera; её выполняют отдельно после проверки окружения.
