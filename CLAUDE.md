# Game — Telegram Mini App, визуальная новелла-антология «Личные дела»

Владелец продукта — Юлия (PM). Код пишет ИИ-агент по шагам дорожной карты ниже.
Этап — **Г1**: прототип эпизода 1 истории «Намертво», тест на 5–8 людях. Гипотезы H1 и H3 считаются
по аналитике (`/api/stats`), поэтому события и первый запуск трогать только осознанно.

**`main` = прод.** Amvera сама собирает и выкатывает каждый коммит в `main` за 2–3 минуты.

## Стек
- Vanilla TypeScript (strict) + Vite 6. Без React и UI-фреймворков. Runtime-зависимостей нет — так и держать.
- Сервер `server/index.mjs` — Node без npm-зависимостей: статика, `POST /api/events`, `GET /api/stats`.
- Деплой: `Dockerfile` (сборка на node:22-alpine → Node-сервер), `amvera.yaml`, постоянный диск `/data`.
- Бюджет: JS + CSS ≤ 50 КБ gzip (проверяет `check:ui`); первый экран ≤ 3 с на мобильном интернете.

## Команды
| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер на 5173, `/api` проксируется на 3000 |
| `npm run dev:server` | локальный сервер аналитики на 3000 |
| `npm run build` | `tsc` + `vite build` |
| `npm run check:ui` | сборка + автопроверка интерфейса; отчёт `.checks/ui/report.html` |

`check:ui` проходит игру в Chromium: 320×568, 390×844, 1440×900 × режимы «браузер» и «Telegram»
(имитация WebApp: подписанный initData, системная «Назад», CloudStorage, home bar 34 px).
На 390 — эпизод целиком, на остальных — до первого выбора. Проверяет: первый запуск, листание, выбор,
паузу, «Назад», меню, сохранение после перезапуска, события аналитики, вызовы Telegram, вёрстку
(горизонтальный скролл, обрезанные блоки, документ зафиксирован, слои z-index, незаполненные
подстановки `{имя}` в текстах, у каждой кнопки есть цель аналитики), бюджет сборки, строки интерфейса
мимо `t()` (кириллица в литералах `src/`), имена событий из каталога и проходят фильтр сервера,
состояние приложения (платформа, маршрут, конфиг). Плюс два сценария: флаги включены через `?ff=` →
баланс и входящие доходят до состояния; конфиг недоступен → игра стартует на значениях по умолчанию.
Плюс регресс (1440 браузер и 320 Telegram): клавиатура (Enter, цифры), «Начать сначала» с диалогом поверх
шторки, эпизод до конца, «Перечитать?» → «Отмена», тост — всё внутри кадра, аналитика нажатий; и перенос
старого сохранения v1. В каждом экране: экраны и слои внутри кадра, чтение — без хедера и таббара, пустые зоны
скрыты; в браузере — три пути «Назад»: Esc, системная «Назад» (история), кнопка на экране.
Плюс стенд каркаса `layout.html` — 8 размеров (телефоны, Telegram fullscreen, режим чтения, телефон боком,
планшет, низкое и обычное окно десктопа): размер и положение кадра, зоны, брейкпоинт `@container`,
`position: fixed` не выходит за кадр. Только стенд: `CHECK_ONLY=shell npm run check:ui`.
Плюс стенд компонентов `kit.html` — 320, 390, 1440: каждое состояние кнопки-иконки, бейджа и чипа есть и видно
(отличается от обычного), зона касания 44 px с углами, круг 40 / 32 px, контраст (текст ≥ 4.5, иконки ≥ 3), подписи
для скринридера, цели аналитики, всё внутри кадра; живые примеры — настоящими нажатиями. На 1440 настоящие
наведение, нажатие и фокус совпадают с замороженными на стенде; на телефоне наведение не «залипает».
Только стенд: `CHECK_ONLY=kit npm run check:ui`.
- `✗` — ошибка, проверка красная. `!` — замечание, не блокирует, но новые замечания перечисляй в отчёте.
- Быстрый прогон части сценариев: `CHECK_ONLY=390-telegram,320-browser npm run check:ui`.
- Браузер: `CHROME_PATH` → Chromium Playwright → Google Chrome → Microsoft Edge.
- Новый экран или элемент → добавь его в сценарий `scripts/check-ui.mjs` в том же шаге.

## Карта кода
- `src/main.ts` — вход: Telegram, аналитика, движок, первый запуск.
- `src/app.ts` — создаёт каркас (экраны — в `shell.content`, слои — в кадр), навигация меню → история → чтение,
  режим каркаса по маршруту (чтение — `immersive`). «Назад»: Telegram BackButton; в браузере — своя кнопка, Esc
  и системная «Назад» (одна страховочная запись в `history`, пока есть куда возвращаться).
- `src/engine.ts` — главы, прогресс, выборы, счётчики. `src/types.ts` — типы главы и каталога.
- `src/storage.ts` — сохранение: сразу `localStorage`, в фоне CloudStorage, при запуске — свежая копия по `savedAt`.
- `src/telegram.ts` — единственная точка доступа к Telegram WebApp. `tg === null` вне Telegram (признак — пустой `initData`).
  `getPlatform()` — telegram / browser, клиент, десктоп ли.
- `src/store.ts` — состояние приложения: `platform`, `config`, `wallet`, `inbox`, `ui.route`.
  `store.get()`, `store.patch(раздел, часть)`, `store.select(выбор, слушатель)`. Прогресс историй сюда не дублируется.
- `src/api.ts` — контракт с сервером (типы ответов) и клиент; вся новая сеть — отсюда. `src/api.mock.ts` — моки до шагов 8.x.
- `src/sync.ts` — сеть → состояние: конфиг при запуске, по флагам — баланс и входящие. Первый экран их не ждёт.
- `public/config.json` — удалённый конфиг: флаги `economy_enabled`, `store_enabled`, `inbox_enabled`, `languages`.
  Меняется коммитом (выкатывается за 2–3 минуты). Нет файла — работают значения по умолчанию (всё новое выключено).
- `src/analytics.ts` — `track()`, пачки в `/api/events` раз в 10 с и при сворачивании (sendBeacon).
- `src/tracking.ts` — каталог событий: `EVENT_NAMES` (продуктовые события, по ним считается отчёт Г1)
  и `UI_TARGETS` (цели нажатий для `ui_tap`: `menu.folder`, `pause.textSize`…); `trackTap()`.
  Кнопка подключается так: `button(класс, содержимое, onClick, attrs, { target, value? })`.
- `src/layout/shell.ts` + `shell.css` — каркас: кадр (на телефоне — весь экран, от 600 px окна — колонка 440 px
  по центру, на десктопе с мышью — «телефон» со скруглениями) и зоны хедер / контент / таббар; слоты `header`,
  `account`, `content`, `tabbar`; режим `immersive` для чтения. Кадр — контейнер `app` и граница для `position: fixed`.
  Хедер и таббар скрыты, пока их слоты пусты (`data-header` / `data-tabbar`): появятся сами на шагах 3–4.
  `layout.html` + `src/layout/preview.*` — стенд каркаса (только dev и `check:ui`, в сборку не входит).
- `src/ui/` — экраны `menu`, `story`, `reading`; `overlay` (шторки, диалоги, тосты со стеком «Назад»; добавляются
  в кадр через `setOverlayHost`); `dom` (`h`, `button`, `icon`).
- `src/ui/kit/` — базовые компоненты, каждый со своим `.css` (префикс `ui-`): `icon-button` (`iconButton`: plain / tonal /
  glass, круг 40 или 32 px, зона касания 44, бейдж, переключатель), `badge` (счётчик, «99+», точка, надпись; 0 — скрыт),
  `chip` (`chip` — метка, `actionChip`, `filterChip`, `chipGroup`). Новые кнопки-иконки, бейджи и чипы — отсюда, не своей
  разметкой; старая `.icon-btn` в `style.css` остаётся до переноса экранов. `kit.html` + `src/ui/kit/preview.*` — стенд
  компонентов (только dev и `check:ui`): все состояния; наведение, нажатие и фокус «заморожены» копиями правил с `data-pseudo`.
- `src/i18n.ts` — `t('ключ', { подстановки })`, формы по числу (`{ one, few, many, other }` + `count`).
  `src/locales/ru.ts` — все строки интерфейса; ключи `экран.смысл` (`menu.title`, `reading.tapHint`).
  Новый язык — файл `src/locales/<код>.ts` с полным переводом; выбор языка игроком — шаг 5.2.
- `src/style.css` — токены (`:root`) и стили. Палитра «cozy dark» своя, не из темы Telegram.
- `public/content/ru/` — `catalog.json` (истории и эпизоды), `ch1.json` (эпизод). Контент правит автор.
- `scripts/check-ui.mjs` — автопроверка. `server/` — сервер и отчёт Г1.

Отладка: `?debug` → в консоли `__game.state()`. Посмотреть выключенное: `?ff=economy_enabled,inbox_enabled`
(флаги управляют только интерфейсом, деньги проверяет сервер).

## Инварианты — не нарушать без отдельного решения владельца
- Первый запуск открывает эпизод 1 без меню (`"firstLaunch": "story"`) — гипотеза H3.
- Сохранение: ключ `game_state`, формат v2 по историям; старые сохранения переносятся автоматически.
- Глава: `id` выбора не меняется после публикации; у экрана либо `next`, либо `choices`; `kind`: `text` | `push` | `end`.
- Имена событий аналитики и поля пачки не менять — по ним считается отчёт Г1.
- `initDataUnsafe` — только для отображения (имя, аватар). Личность игрока — только `initData` с проверкой подписи на сервере.
- Telegram API — только через `telegram.ts`, с проверкой версии (`supports`) перед вызовом.
- Деньги (с Г3): баланс, покупки, промокоды — только на сервере, баланс — журнал записей. Цифровые товары в Telegram — только Stars.

## Правила изменений — обязательны на каждом шаге
1. Меняй только файлы, перечисленные в задаче. Нужен другой — остановись и спроси.
2. Запрещены заглушки вместо кода: «// ...», «// код без изменений», «остальное как было».
   Существующие файлы — только точечными правками. Целиком пишется только новый файл.
3. Не удаляй и не переименовывай существующие функции, экспорты, CSS-классы, data-атрибуты, ключи
   сохранения. Если удаление нужно — перечисли и спроси.
4. CSS: стили нового компонента — в его собственном файле, с префиксом (`.hdr-wallet__*`). Запрещены теговые
   и глобальные селекторы, правка `:root` и `style.css` без запроса, `!important`, цвета мимо переменных.
   z-index — только токенами `var(--z-*)` из `:root`: raised 1, controls 2, hud 3, chrome 10, popover 30,
   layer 50, toast 60. Новый слой — новый токен в шкале, не число в компоненте.
   Адаптивность внутри кадра — только `@container app (…)`: на десктопе кадр 440 px при окне 1440, и
   `@media` по ширине окна там врёт. `@media` по окну — только для самого кадра в `shell.css`.
   Доли высоты — `cqh` (высота кадра), перед ним запасная строка с `vh` для старых WebView.
5. Telegram — только через `telegram.ts`. Тексты интерфейса (включая `aria-label` и всплывашки) — только
   `t()`: новая строка = ключ в `src/locales/ru.ts`. Фразу целиком — в словарь с подстановками, не склеивать
   из кусков (`Дело № {no}`, а не `'Дело № ' + no`). Контент (главы, каталог), `console.*` и `new Error()` —
   не через `t()`. Новая сеть — только через `api.ts`; существующие `fetch` в `engine.ts`
   и `analytics.ts` не трогать. Компоненты не ходят в сеть: `api.ts` → `sync.ts` → `store` → компонент.
   Новый раздел состояния или эндпоинт — сначала тип в `store.ts` / `api.ts`, потом мок, потом интерфейс.
6. Деньги, покупки, промокоды — только отображение ответа сервера. Никаких расчётов и оптимистичных
   начислений на клиенте.
7. `storage.ts` и формат сохранения не трогать без отдельной задачи.
8. Новые npm-зависимости — только с согласия. Runtime-зависимостей нет; dev: typescript, vite, playwright-core.
9. Каждая кнопка — с целью аналитики: последний параметр `button()` — `{ target: 'экран.элемент', value? }`.
   Новая кнопка = новая цель в `UI_TARGETS` (`src/tracking.ts`), а не новое имя события. Новое продуктовое
   событие (шаг воронки, метрика) — в `EVENT_NAMES`, только `a-z` и `_` до 40 символов: остальное сервер
   выбрасывает молча. Если нажатие уже пишет продуктовое событие — `silent: true`, без дубля.
10. Перед сдачей `npm run check:ui` зелёная (сборка входит в неё). Скриншоты затронутых экранов — посмотреть.
11. Отчёт: изменённые файлы; что добавлено; что удалено (ожидаемо — «ничего»); новые замечания `check:ui`;
    как проверить руками. Код в чат не выводить.
12. Один шаг — один коммит в ветке `feature/*`. В `main` не пушить: это прод.
13. Задача требует больше 3 файлов или противоречит правилам — сначала план, потом код. Исключение — шаг
    дорожной карты, где список файлов уже согласован.
